# Debug Log Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Debugging toggle that writes a redacted, size-capped debug log next to the exe, with exception detail and an ntfy.sh network check.

**Architecture:** Platform-neutral `DebugLogFile` (write/rotate/redact), `DebugReport` (exception chain, header), `NetworkProbe` (proxy/DNS/TCP/HTTPS with injectable steps). A static `DebugTrace` sink is attached while debugging is on; `MainWindow.AddLog` mirrors into it; workers add detail.

**Tech Stack:** .NET 10, WPF, xUnit (tests link platform-neutral sources).

**Spec:** docs/superpowers/specs/2026-11-14-debug-log-design.md

## Global Constraints

- File names: `NotiRelay-debug.log`, `NotiRelay-debug.old.log`; cap 5 MB per file.
- Fallback folder: `%LOCALAPPDATA%\NotiRelay`.
- Health URL: `https://ntfy.sh/v1/health`; per-step timeout 10 s.
- Topic never written: replace `ntfy.sh/<topic>` always, bare topic when length ≥ 4, with `NtfyTopic.Mask`.
- Code and log text in English.

## Review Focus

- Exe folder read-only (Program Files) → falls back, does not crash.
- Write failure mid-run (disk full, file locked) → on-screen warning once, app keeps working.
- Proxy URI with credentials → credentials never written.
- Logging from worker threads concurrently → no interleaved/corrupt lines (lock).
- WPAD proxy lookup blocking → network check runs off the UI thread.
